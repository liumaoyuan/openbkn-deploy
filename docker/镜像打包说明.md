# OpenBKN 离线镜像打包说明

**适用对象**：在能上外网的机器上制作离线包的人。
**产出**：一个可以直接拷到内网机的 `openbkn-deploy` 目录（约 2.9 GB）。
**交付给现场后**：按同目录下的《内网部署说明.md》操作。

---

## 一、目录结构

### 1.1 打包前的源码目录

`bkn-foundry`、`bkn-studio`、`openbkn-deploy` 三个目录必须保持同级，`compose.yml` 里的构建路径是相对 `openbkn-deploy/docker` 写的：

```
E:\workspace\qy\openbkn\
├── bkn-foundry\                 后端源码（构建镜像）
├── bkn-studio\                  前端源码（构建镜像）
└── openbkn-deploy\
    ├── docker\                  部署与打包脚本
    │   ├── compose.yml          服务编排
    │   ├── .env.example         配置模板（复制为 .env）
    │   ├── config.template\     运行时配置模板
    │   ├── render-config.sh     配置渲染脚本（内网机启动时用）
    │   ├── gateway.conf         网关路由
    │   ├── proxy-headers.conf   网关代理头
    │   ├── mariadb-init.sql     数据库初始化
    │   ├── package-images.sh    打包脚本（Git Bash）
    │   ├── package-images.ps1   打包脚本（PowerShell）
    │   ├── load-images.sh       导入脚本（内网机用）
    │   ├── load-images.ps1      导入脚本（内网机用）
    │   ├── install-docker.sh    内网机装 Docker
    │   ├── 本文件.md
    │   └── 内网部署说明.md
    └── build\                   打包产物（自动生成，不要手工改）
        ├── openbkn-images.tar
        ├── openbkn-images.tar.sha256
        └── images.txt
```

### 1.2 打包后的交付目录

```
openbkn-deploy\                  整体拷到内网机
├── docker\
│   ├── compose.yml
│   ├── .env                     ← 已填写密码
│   ├── config.template\
│   ├── render-config.sh
│   ├── gateway.conf
│   ├── proxy-headers.conf
│   ├── mariadb-init.sql
│   ├── install-docker.sh
│   ├── load-images.sh / .ps1
│   ├── 镜像打包说明.md
│   ├── 内网部署说明.md
│   └── app\<架构>\              Docker 安装包（约 140 MB）
│       ├── docker-28.5.2.tgz
│       └── docker-compose-linux-<架构>
└── build\
    ├── openbkn-images.tar       2.7 GB
    ├── openbkn-images.tar.sha256
    └── images.txt
```

`docker\config\`（渲染结果）不需要交付，内网机启动时会自动生成。

## 二、准备环境

- Docker Desktop（Windows/macOS），Linux 容器模式
- 至少 40 GB 可用磁盘（镜像包约 2.8 GB，构建缓存更大）
- 不需要 Python 或其他运行时

## 三、准备 Docker 安装包（首次打包时做一次）

按内网机的 CPU 架构下载，放到 `docker/app/<架构>/`：

```
docker/app/
├── amd64/
│   ├── docker-28.5.2.tgz
│   └── docker-compose-linux-x86_64
└── arm64/
    ├── docker-28.5.2.tgz
    └── docker-compose-linux-aarch64
```

下载地址：

```
# Docker 静态包（x86_64）
https://mirrors.tuna.tsinghua.edu.cn/docker-ce/linux/static/stable/x86_64/docker-28.5.2.tgz
https://mirrors.ustc.edu.cn/docker-ce/linux/static/stable/x86_64/docker-28.5.2.tgz

# Docker 静态包（aarch64，飞腾/鲲鹏）
https://mirrors.tuna.tsinghua.edu.cn/docker-ce/linux/static/stable/aarch64/docker-28.5.2.tgz
https://mirrors.ustc.edu.cn/docker-ce/linux/static/stable/aarch64/docker-28.5.2.tgz

# Compose 插件
https://github.com/docker/compose/releases/download/v2.32.4/docker-compose-linux-x86_64
https://github.com/docker/compose/releases/download/v2.32.4/docker-compose-linux-aarch64
https://github.com/docker/compose/releases/download/v2.32.4/checksums.txt
```

Compose 插件下载后可用 `checksums.txt` 校验：

```bash
cd docker/app
sha256sum -c checksums.txt --ignore-missing
```

## 四、填写 `.env`

```powershell
cd E:\workspace\qy\openbkn\openbkn-deploy\docker
Copy-Item .env.example .env
```

打开 `.env`，按注释把所有 `CHANGE_ME_*` 换成强密码。生成随机密码：

```powershell
-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 32 | ForEach-Object {[char]$_})
```

```bash
openssl rand -base64 24
```

注意：

- `OSS_CRYPTO_AES_KEY` 必须正好 32 个字符
- 密码不要包含空格和 `#`
- `OPENBKN_PUBLIC_BASE_URL` 可以先用 `http://localhost:8080`，**现场部署时由内网人员改成实际 IP**；启动时 OAuth 客户端的回调地址会按这个值自动更新
- 如果要同时服务多个客户，推荐每个客户单独一份 `.env`（重新生成密码），不要共用

`.env` 包含全部密码，交付时按敏感资料管理。

## 五、打包镜像

Git Bash：

```powershell
cd E:\workspace\qy\openbkn\openbkn-deploy\docker
bash package-images.sh
```

纯 PowerShell：

```powershell
Set-Location E:\workspace\qy\openbkn\openbkn-deploy\docker
powershell -ExecutionPolicy Bypass -File .\package-images.ps1
```

只查看镜像清单、不导出：

```powershell
bash package-images.sh --list
```

### 产物

`openbkn-deploy\build\`：

| 文件 | 说明 |
|---|---|
| `openbkn-images.tar` | 23 个镜像（14 个应用 + 9 个运行期依赖），约 2.7 GB |
| `openbkn-images.tar.sha256` | 校验和 |
| `images.txt` | 镜像清单 |

### 构建来源

镜像由 `docker compose build` 从**本机工作区源码**构建（`../../bkn-foundry`、`../../bkn-studio`），不使用 GitHub Actions 的发布产物。

因此镜像内容取决于当前工作区状态。正式交付前请确认：

```powershell
cd E:\workspace\qy\openbkn\bkn-foundry
git status
git log -1 --oneline

cd ..\bkn-studio
git status
git log -1 --oneline
```

工作区有未提交改动时，建议先提交或确认改动是有意为之。

## 六、核对与交付

### 6.1 校验产物

```bash
cd openbkn-deploy/build
sha256sum -c openbkn-images.tar.sha256
```

### 6.2 按架构拷贝

先确认内网机架构（`uname -m`：`x86_64` 或 `aarch64`），只拷对应目录即可。

```powershell
$src = "E:\workspace\qy\openbkn\openbkn-deploy"
$dst = "E:\to-intranet\openbkn-deploy"
New-Item -ItemType Directory -Force "$dst\docker","$dst\build" | Out-Null

Copy-Item "$src\docker\compose.yml","$src\docker\.env",
          "$src\docker\gateway.conf","$src\docker\proxy-headers.conf",
          "$src\docker\mariadb-init.sql","$src\docker\render-config.sh",
          "$src\docker\install-docker.sh","$src\docker\load-images.sh",
          "$src\docker\load-images.ps1",
          "$src\docker\镜像打包说明.md","$src\docker\内网部署说明.md" "$dst\docker"

Copy-Item -Recurse "$src\docker\config.template" "$dst\docker\config.template"

# 按架构二选一
Copy-Item -Recurse "$src\docker\app\amd64" "$dst\docker\app\amd64"
# Copy-Item -Recurse "$src\docker\app\arm64" "$dst\docker\app\arm64"

Copy-Item "$src\build\openbkn-images.tar",
          "$src\build\openbkn-images.tar.sha256",
          "$src\build\images.txt" "$dst\build"
```

### 6.3 交付清单

- `docker\`（含 `.env` 与 `config.template\`）
- `docker\app\<架构>\`（Docker 安装包）
- `build\openbkn-images.tar` + `.sha256`

**不要**交付：`bkn-foundry`、`bkn-studio` 源码、`docker\config\`、另一架构的 `app\` 子目录、`build\` 下的历史产物。

## 七、常见问题

**构建时拉包失败**

构建阶段需要访问镜像仓库、Go 模块代理、PyPI、npm。仓库里已经配好国内镜像源；如果仍然失败，检查 Docker Desktop 的代理/DNS，或参考 `compose.yml` 顶部各服务的 `GOPROXY_URL`、`PIP_INDEX_URL`、`NPM_REGISTRY` 参数。

**磁盘空间不足**

构建缓存加镜像包通常需要 40 GB 以上；可执行 `docker system prune` 清理旧缓存后重试。

**镜像 tag 不对**

应用镜像统一命名为 `openbkn/<service>:<tag>`，`<tag>` 取自 `.env` 的 `OPENBKN_IMAGE_TAG`（默认 `local`）。改名后需要重新打包。

**内网机架构不一致**

amd64 的镜像包不能导入 arm64 机器。鲲鹏/飞腾机器必须使用 `--platform` 构建的 arm64 镜像包，无法在一台 x86 机器上直接产出，需要 arm64 构建机或 buildx 跨架构构建。
