# OpenBKN 内网部署说明

**适用对象**：在内网（不能上网）的机器上部署 OpenBKN 的现场人员。
**前提**：已经拿到打包好的 `openbkn-deploy` 目录（由《镜像打包说明.md》产出）。

---

## 一、确认拿到的内容

```
openbkn-deploy\
├── docker\
│   ├── compose.yml              服务编排
│   ├── .env                     配置与密码（通常只需改 2 行）
│   ├── config.template\         配置模板
│   ├── render-config.sh         启动时自动渲染配置
│   ├── gateway.conf             网关路由
│   ├── proxy-headers.conf       网关代理头
│   ├── mariadb-init.sql         数据库初始化
│   ├── install-docker.sh        安装 Docker
│   ├── load-images.sh / .ps1    导入镜像
│   ├── 镜像打包说明.md           上一步的说明（不用看）
│   └── 内网部署说明.md           本文件
│   └── app\<架构>\              Docker 安装包
│       ├── docker-28.5.2.tgz
│       └── docker-compose-linux-<架构>
└── build\
    ├── openbkn-images.tar       镜像包（约 2.7 GB）
    ├── openbkn-images.tar.sha256
    └── images.txt
```

**`docker` 和 `build` 必须保持并列**，`load-images.sh` 默认从 `../build/` 读镜像包。

建议机器配置：8 核 CPU、16 GB 内存、40 GB 可用磁盘。

---

## 二、检查环境

```bash
uname -m          # x86_64 或 aarch64
uname -r          # 内核版本，麒麟 V10 一般为 4.19
cat /etc/os-release
free -h
df -h /
```

`uname -m` 的结果决定后面用 `app/amd64` 还是 `app/arm64`。

---

## 三、安装 Docker

在 `openbkn-deploy/docker` 目录下执行，脚本会自动识别 CPU 架构并从 `app/<架构>/` 选择安装包：

```bash
sudo bash install-docker.sh
```

安装前可以先确认脚本识别到的文件是否正确（不需要 root）：

```bash
bash install-docker.sh --check
```

输出示例：

```
架构        : x86_64 (app/amd64)
Docker 包   : .../app/amd64/docker-28.5.2.tgz
Compose 插件: .../app/amd64/docker-compose-linux-x86_64
```

脚本会安装 Docker 引擎与 Compose 插件、写入日志轮转配置、启动服务，最后自动检查。看到类似输出即成功：

```
Docker Engine 28.5.2 (linux/amd64)
Docker Compose version v2.32.4
```

> 如果安装包不在默认位置，也可以手动指定：
> `sudo bash install-docker.sh <docker.tgz> <docker-compose 文件>`

---

## 四、导入镜像

```bash
cd /path/to/openbkn-deploy/docker
bash load-images.sh
```

脚本会：校验 sha256 → `docker load` 导入 → 按 compose 清单逐个核对镜像是否存在、架构是否匹配。

最后看到 `全部镜像就绪` 即可。

> 导入镜像和下一步修改 `.env` 的先后顺序可以互换，只要都在启动（第六章）之前完成就行。

---

## 五、修改 `.env`（通常只改两行）

打开 `docker/.env`，修改访问地址：

```
OPENBKN_PUBLIC_BASE_URL=http://192.168.1.100:8080
OPENBKN_BIND_ADDRESS=0.0.0.0
```

- 第一行换成**用浏览器访问这台机器时实际使用的地址**（IP 或域名，端口、http/https 都要一致）
- 第二行 `0.0.0.0` 表示允许其他机器访问；保持 `127.0.0.1` 则只能本机访问

改完继续第六章启动；环境已经在运行时，同样执行第六章的命令即可生效。

其余密码项如果交付时已经填好，不需要改动。

> 密码是第一次启动时写进数据库的。如果这是**全新部署**（数据目录为空），也可以在这一步修改密码；如果机器上已有旧数据，改密码不会生效，需要按数据库方式轮换。

## 六、启动

```bash
docker compose --env-file .env up -d
```

首次启动会依次执行：

1. `config-init`：按 `.env` 生成应用配置到 `docker/config/`
2. 启动 MariaDB、Redis、Kafka、OpenSearch、MinIO 等基础服务
3. `data-migrator`：初始化数据库、执行迁移
4. 启动应用服务与网关

大约需要 1~3 分钟。查看进度：

```bash
docker compose --env-file .env ps
```

全部显示 `Up`（基础服务显示 `Up (healthy)`）即启动完成。

> 如果提示 `image not found` 或 `No such image`，说明还没导入镜像，先执行第四章的 `bash load-images.sh`。`compose.yml` 对运行期镜像设置了 `pull_policy: never`，内网机不会尝试联网拉取。

> `docker/config/` 是自动生成的，不要手工编辑。需要改配置请改 `.env`，然后重新 `up -d`。

## 七、登录

浏览器打开：

```
http://192.168.1.100:8080/studio/
```

- 用户名：`admin`
- 初始密码：`.env` 里的 `BKN_SAFE_INITIAL_PASSWORD`

查看密码：

```bash
grep BKN_SAFE_INITIAL_PASSWORD .env
```

> 首次登录后请尽快修改管理员密码；之后再改 `.env` 里的初始密码不会影响已有账号。
> 第一次打开页面如果显示异常，按 `Ctrl+Shift+R` 强制刷新一次。

## 八、日常操作

```bash
cd /path/to/openbkn-deploy/docker

docker compose --env-file .env ps                  # 查看状态
docker compose --env-file .env logs -f gateway     # 网关日志
docker compose --env-file .env restart             # 重启全部
docker compose --env-file .env down                # 停止（保留数据）
docker compose --env-file .env up -d               # 再次启动
```

> **不要执行 `docker compose down -v`**：它会删除所有数据卷，数据无法恢复。

### 版本升级

1. 把新的 `openbkn-images.tar`（和 `.sha256`）拷到 `build/`，覆盖旧文件；
2. `bash load-images.sh`；
3. `docker compose --env-file .env up -d`。

数据库升级由 `data-migrator` 自动完成，命名卷里的数据会保留。`.env` 一般可以沿用。

## 九、常见问题

**页面打不开**

1. 确认防火墙放行了 8080 端口；
2. 确认 `.env` 是 `OPENBKN_BIND_ADDRESS=0.0.0.0`；
3. 确认浏览器地址和 `OPENBKN_PUBLIC_BASE_URL` 完全一致。

**登录失败 / 页面反复刷新**

访问地址与 `OPENBKN_PUBLIC_BASE_URL` 不一致。改完 `.env` 后：

```bash
docker compose --env-file .env up -d
```

**页面显示 OAuth2 错误：`redirect_uri` does not match**

浏览器访问的地址和 `.env` 里的 `OPENBKN_PUBLIC_BASE_URL` 不一致（例如用 IP 访问，但 `.env` 还是 `localhost`）。

1. 把 `.env` 的 `OPENBKN_PUBLIC_BASE_URL` 改成浏览器地址栏里的地址；
2. `docker compose --env-file .env up -d`；
3. 浏览器强制刷新（`Ctrl+Shift+R`）后重新登录。

启动时 `hydra-client-seed` 会用新地址更新 OAuth 客户端，不需要手工操作 Hydra。

**服务报认证失败 / Access denied**

这是密码不一致。**不要改 `config/`**（会被覆盖），直接改 `.env` 里对应密码后 `up -d`。
只有全新部署（数据为空）才能改密码。

**首次启动卡在 mariadb unhealthy**

机械硬盘上首次初始化 MariaDB 可能要好几分钟。compose 默认的健康检查等待时间已放宽到约 13 分钟；如果仍然在首次启动时报 `container openbkn-mariadb-1 is unhealthy`：

1. 先确认它其实已经起来了：`docker compose --env-file .env ps`
2. 如果显示 `Up (healthy)`，直接再执行一次 `docker compose --env-file .env up -d`，其余服务会继续启动
3. 如果一直是 `restarting`，再按下面的 Docker 日志排查

**Docker 起不来**

```bash
journalctl -u docker -n 100 --no-pager
```

麒麟 V10 还要确认 KySec 没有拦截 `dockerd`、`containerd` 或内核模块。

**端口被占用**

修改 `.env` 的 `OPENBKN_HTTP_PORT`，同时改 `OPENBKN_PUBLIC_BASE_URL` 的端口，然后 `up -d`。

**想完全重建运行时配置**

```bash
docker compose --env-file .env down
rm -rf config
docker compose --env-file .env up -d
```

不要在容器运行期间直接删除 `config/`，否则 Docker Desktop 环境可能残留挂载缓存。

## 附录：可选——安装宿主机 MySQL

安装包已随包提供：

```
app/<架构>/mysql-8.0.45-linux-glibc2.28-<架构>.tar.xz
```

执行（可先用 `--check` 确认脚本识别到的安装包）：

```bash
cd /path/to/openbkn-deploy/docker
bash install-mysql.sh --check
sudo bash install-mysql.sh
```

脚本会自动按 CPU 架构选择安装包，完成：

- 安装到 `/opt/mysql-8.0.45`
- 注册 systemd 服务 `openbkn-mysql`（端口 3306，开机自启）
- 创建数据库 `openbkn` 和账号 `openbkn`@`%`
- 导入时区数据
- 把连接信息和随机密码写入 `/root/openbkn-mysql-credentials.txt`（权限 0600）

可用环境变量覆盖默认值：

```
MYSQL_PORT=3306
OPENBKN_DB_NAME=openbkn
OPENBKN_DB_USER=openbkn
MYSQL_ROOT_PASSWORD=<自定义 root 密码>
MYSQL_PASSWORD=<自定义业务密码>
```

## 十、安全提醒

- 只有网关的 8080 端口暴露给宿主机，数据库、Redis、Kafka、OpenSearch 等只在 Docker 网络内可见。
- `.env` 保存全部密码，请按敏感资料保管，不要截图或外传。
- 本栈未配置 TLS；若要开放给不可信网络，请在前面加一层 HTTPS 反向代理。
- OpenSearch 在开发栈中关闭了安全插件，不要在生产环境复用此配置。
- 数据库、对象存储的密码第一次启动后就固定了，修改 `.env` 不会自动轮换。
